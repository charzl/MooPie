# 贡献与文档写法

先读 [agent.md](../../agent.md) 的仓库约定，按[架构参考](../reference/architecture.md)找到修改位置。文档按开始使用、任务指南、接口参考和贡献资料组织；新页面加入[导航](../README.md)。

## 修改流程

1. 检查分支和本地修改，明确本次要改变的行为。
2. 修改实现和相应文档。策略只维护独立 `put_rules.py`；新增指标或修改默认规则时同步更新规则版本。
3. 用合成数据验证必要行为，按[测试指南](../guides/functional-testing.md)选择范围。真实行情只在本地只读验证。
4. 检查 diff、相对链接、示例参数及输出说明。按用户批次安排交付，见[GitHub 指南](../guides/github-workflows.md)。

## 文档放在哪里

| 内容 | 位置 | 应回答的问题 |
| --- | --- | --- |
| 第一次安装与体验 | `getting-started/` | 从未配置到可用需要什么？ |
| 完成一项任务 | `guides/` | 先做什么、怎样验证、失败看哪里？ |
| 查字段、参数、约定 | `reference/` | 接受什么输入，返回什么，边界是什么？ |
| 规则与评分公式 | 现有 [put-scoring.md](../put-scoring.md) 和[规则说明](../../modules/put-screener/README.md) | 计算与假设是什么？ |
| 维护规范与模板 | `contributing/` | 后续如何保持文档一致？ |

README 保留面向用户的安装与核心入口；agent.md 保留 agent 必需约束和导航。详细任务流程链接到 guides，不在多个页面复制整套公式。

## 写作约定

使用中文解释，代码、字段和参数保留实际名称。标题说明任务，步骤按执行顺序写；命令注明操作系统、工作目录、依赖、输出位置及验证方法。PowerShell 示例不使用 Bash 的续行或环境变量语法。

参数与命令以实现的 `--help` 和源码为准，错误格式写清具体入口。不要把构建描述成发布，把合成测试描述成真实账号验证，或把规划能力写成已实现。日期范围注明是否包含当天，收益注明百分数值与费用口径，数据注明时点。

使用仓库内相对链接。示例使用合成数据或不含个人信息的代码；本地真实查询结果不写入文档。引用外部材料时保留来源及适用范围，复用文件时先检查许可与署名要求。

## 可复用模板

以下为本仓库按当前工作流编写的简短模板，复制后替换占位符并删除不适用内容：

- [任务指南](templates/how-to.md)：前提、步骤、结果、验证与失败处理。
- [接口参考](templates/reference.md)：参数、类型、单位、输出与错误。
- [故障排查](templates/troubleshooting.md)：现象、证据、处理与恢复验证。
- [变更说明](templates/change-notes.md)：问题、行为、验证和必要迁移说明。
