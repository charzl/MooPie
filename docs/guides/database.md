# 本地数据库与盘中 / 盘后查询

使用 Python 自带 SQLite，无需安装服务。桌面、CLI 和 MCP 共用存储，独立规则引擎仍只分析输入，不直接访问 OpenD 或数据库。

桌面默认读取已保存的收盘结果（研究 CLI `--saved`），包括盘中打开时：先看上一完成交易日；收盘后优先看当天已保存的收盘数据。没有当天收盘采集时显示较早的真实日期及更新提示，不会自动连接 OpenD 刷新已有股票。启动自动查看整个 Watchlist；从未采集过的单股首次手动查询仍自动抓取。刷新放在页签外右下角，首次安装也从这里采集。

Put 报告以 `research_put_report` 操作存入现有 `snapshots` 表，复用压缩、校验和清理，不增加表。键包含股票范围、原始快照ID、Filter、Sort、Top 和分析代码版本；相同输入直接复用预计算报告，变更条件才离线重算。升级前只有原始行情时，首次读取离线生成报告。主动更新后的合格收盘报告也会保存；盘中更新独立展示，不替换默认收盘结果。多股只合并同一交易日，缺失成员明确说明。应用关闭期间不会自行采集当天收盘数据。

下面是原始采集 CLI / MCP 的默认路由（桌面主动更新也复用这一层）：

| 情况 | 默认行为 |
| --- | --- |
| 对应市场处于查询时段内 | 读取 OpenD，保存原始快照，再分析 |
| 盘后、周末或休市 | 优先查询 SQLite，使用最近对应交易日的匹配快照 |
| 数据库没有匹配数据 | 自动连接 OpenD 抓取并保存；已有匹配数据的股票不重抓，失败明确报错 |
| 主动选择「更新行情」/ CLI `--update` | 逐股复用有效缓存，只连接 OpenD 补抓缺失或过期项，包括盘后 |
| 「更新行情」右侧菜单「强制刷新全部」/ `--refresh` / MCP `refresh=true` | 所有请求都连接 OpenD 并保存，包括盘后 |
| 修改 Filter、排序、Top 数量 | 对已有完整输入离线重算，不抓取行情 |

首次使用可以在桌面点击「更新行情」。完整 Put 采集也会将取得的日线保存为趋势查询可复用的快照。相同查询参数下，批量采集会另外保存各只股票 / 合约的快照，支持单独查询、子集查询和调整列表顺序；独立采集过的多只股票也可以组合读取。月份、端口和日期区间等仍须匹配，不会拿一月期权范围冒充三月范围。`doctor` 始终测试真实 OpenD，不会读缓存。

增量更新不是“有记录就永远不更新”：盘中报价默认60秒有效，达到边界就过期，CLI 用 `--max-age-seconds 1..3600` 调整。显式更新在盘后只复用最近对应交易日、收市后采集的匹配快照；旧交易日或仅有盘中快照会补抓。证券身份按对应交易日缓存，日线按最近完成交易日判断，不因盘中尚无当天完成K线而每分钟重抓昨日数据。普通盘后查询优先使用匹配缓存，缺失时自动抓取；混合名单只补抓缺少成员。已有盘中快照仍保留原始时间和“非收盘”标记，需要主动更新才能取得收盘后版本。更新失败不拿旧数据冒充成功；MCP的 refresh 仍强制重抓。

```sh
# 首次或主动更新：需要已登录 OpenD
./moomoo collect AVGO --months 3 --update --output artifacts/input.json
# 盘后再次查询：仅从数据库读取同一请求
./moomoo collect AVGO --months 3 --output artifacts/cached-input.json
apps/python/.venv/bin/python -m moopython.research_cli trend AVGO
```

桌面启动时不再自动启动 OpenD，盘后可直接使用已有数据库。需要连接时可点「启动 OpenD」；源码安装仍需自行安装、登录官方程序。

## 时段与数据日期

时段使用 `America/New_York`，考虑夏令时、周末、正常节假日及半日市。本地日历覆盖 2025–2028；超出范围会报错，需更新 `market_sessions.py`，不会猜测。正常交易日参考 [NYSE 官方日历](https://www.nyse.com/trade/hours-calendars)。

期权使用保守的查询窗口：常规日 9:30–16:15，半日市截至13:15，覆盖部分产品延迟收市的情况；这不代表每个合约在整个窗口都可交易。按 [Cboe 公告](https://www.cboe.com/notices/content/?id=62044)，2026-10-19 起，对所列合资格股票 / ETF 纳入7:30–9:25的延长时段，9:25–9:30休息。资格名单是有版本的本地配置，应跟随交易所后续调整更新。股票快照另用包含夜盘的保守窗口，不能沿用期权收市时间。实际市场状态和报价时间仍以原始 OpenD 字段为准。

盘后返回的 `data_access` 说明 `source=database`、快照ID、采集时间、交易日和时段判定。原始 `collected_at`、报价更新时间、日线截至日期保持不变。盘中保存的快照会标明“非收盘快照”；保存时间也不等于报价最后更新时间。日线缓存若缺少最近已完成交易日，默认趋势查询会要求主动刷新。行情、财报日历及合约表可能在不同时间更新，数据库快照只是其采集时点的记录。

## 文件位置与历史保留

| 系统 | 默认路径 |
| --- | --- |
| macOS | `~/Library/Application Support/MooPie/market.sqlite3` |
| Windows | `%LOCALAPPDATA%\MooPie\market.sqlite3` |
| Linux | `$XDG_DATA_HOME/MooPie/market.sqlite3`，默认 `~/.local/share/MooPie/market.sqlite3` |

可在启动程序或 MCP 宿主前设置 `MOOMOO_DB_PATH` 为同一个绝对路径。桌面子进程继承该变量。SQLite 与项目代码、虚拟环境分开保存，升级程序不删除行情。

按请求与交易日索引原始 JSON，zlib 无损压缩后追加存储，并验证校验和；不保存另一套评分公式。每次真实成功采集保留版本，最新记录按原始采集时间选择。仅保存程序实际采集过的数据，无法凭数据库补回未抓取过的历史 Bid / Ask。

## 多股票 schema

使用一张 `snapshots` 表存所有股票，没有“一只股票一张表”。schema 版本9由 `PRAGMA user_version` 标记；旧版自动事务迁移，保留原始ID、压缩行情和校验和，失败会回滚，不需要重新采集。v3新增 `securities` 和 `security_aliases`，v4新增 `watchlist`；v5新增模拟盘的实验、客户、审计输入、成交和估值五张表；v6新增 `price_signals` 表，按股票、日线日期、报价时间和算法版本保存支撑阻力及完整证据；v7新增 `buy_alerts` 表，保存开启提醒时选定的支撑区、最近报价时间与提醒状态；v8给提醒增加确认方式、进入区间时间和最近处理的日线日期，旧提醒默认按报价确认；v9新增 `order_book_history`，保存个股详情实际采样的可见盘口快照。目前共13张应用表，已有行情和证券目录不重建。模拟盘账本、审计输入、价格信号和提醒记录不参加行情快照清理，详见[模拟盘存储](paper-trading.md#保存与升级)。盘口采样历史按股票最多保留 1440 条，与原始行情快照保留期分开。

结构定义独立放在 [`moopython/database/migrations`](../../apps/python/moopython/database/migrations)，按版本顺序执行；已应用的迁移不修改，新增结构用下一个版本。SQL 定义表和索引，Python 迁移钩子仅负责从旧 `request_key` 补充股票与操作类型。所有待执行步骤、数据转换和版本号在同一事务内完成；当前版本的库不会重建。

可直接查看自动生成的 [`schema.sql`](../../apps/python/moopython/database/schema.sql)，或执行 `./moomoo db schema` 输出当前结构。该命令在内存中重放迁移，不打开个人行情库、不连接 OpenD。`schema.sql` 供查阅，不用于直接升级现有数据库。

开发时更新迁移后，运行 `apps/python/.venv/bin/python scripts/export-database-schema.py` 重新生成；加 `--check` 只检查是否一致。独立 SQL 文件随 wheel 和桌面包分发，不要求用户手动执行 SQL。

个股详情的有效支撑阻力保存在 `price_signals` 表；每条记录含日线截止日、当时的参考价和报价时间、算法版本、计算时间及完整区间与转折证据。同一报价时间重复计算会更新同一条记录，不同时间保留历史。用 `./moomoo db price-signals AVGO --limit 20` 可读取该股历史 JSON，无需连接 OpenD。

买点条件提醒保存在 `buy_alerts` 表，每只股票一条，记录开启时的支撑上下沿、日线日期、状态、确认方式、进入支撑区时间及最近处理的报价和日线日期。状态变化后重新打开桌面仍可查看；只有桌面程序运行且 OpenD 可用时才继续检查。计划器输入的投入金额和风险预算不保存，也不会创建真实委托。

| 字段 | 作用 |
| --- | --- |
| `id` | 永不复用的自增快照ID，清理后不会指向另一条新数据 |
| `symbol` | 单股记录的市场前缀股票代码，例如 `US.AVGO`；整批或全市场日历为空 |
| `operation` | 期权完整输入、期权链、日线、快照或财报查询的操作类型 |
| `batch_id` | 将同一批采集的整批记录、单股记录和日线关联起来 |
| `request_key` | 包含来源、端口、操作和实际查询参数，避免误用不同范围的数据 |
| `session_date` | 对应交易日，用于盘后查询匹配 |
| `fetched_at`、`saved_at` | UTC 原始采集时间、入库时间；清理按前者判断 |
| `checksum`、`payload` | 原始 JSON 的 SHA-256 和无损压缩数据 |

索引覆盖请求＋交易日＋时间、股票＋操作＋交易日＋时间、批次和清理时间。`settings` 表保存保留天数、上次清理时间及 Watchlist 首次初始化 / 迁移标记。完整合约代码、所属股票、到期日、Put/Call、行权价、币种、合约乘数和报价时间等保留在原始 `payload`，当前没有拆成每张合约一行的 SQL 行情表；跨合约 SQL 指标筛选仍由独立规则引擎对还原的输入完成。

例如采集 `[AVGO, NVDA]` 后，可以直接查询 AVGO 或 `[NVDA, AVGO]`。后来只刷新 AVGO，重新查询列表会使用 AVGO 新快照和 NVDA 原快照，`data_access.members` 分别列出真实采集时间和ID，不宣称两只股票同时报价。缺少某只股票时明确列出缺失代码，保留其他股票的数据，不悄悄返回不完整的股票名单。

数据库不限制总股票数；底层批量采集 API 每次最多20只股票，Watchlist 研究逐只调用，不需要修改 schema。桌面支持单股 / 全名单搜索及核验后加入，详情见 [Watchlist](watchlists.md)。

`securities` 以自增 `id` 为主键，`code` 唯一，包含代码、名称、规范化名称、证券类型、状态、来源及更新时间。`security_aliases` 通过 `security_id` 外键关联；复合主键为 `(security_id, normalized_alias)`，允许多个证券拥有同一别名。索引支持代码、名称与别名前缀；通配符中间匹配扫描本地目录。股票目录 / 别名不参与快照保留期清理；同步是显式动作，不跟随每次打字或行情查询发生。见[名称搜索](watchlists.md#公司名别名与候选选择)。

## 自动与手动清理

`watchlist` 使用 `id` 自增主键、`symbol` 唯一约束，包含 UTC `added_at` 和加入来源 `source`；按ID保持加入顺序。不强制外键依赖完整证券目录，新增仍由券商身份资料验证。首次访问时把旧 JSON 的成员和初始化标记放在同一事务中写入，后续只查表，旧文件修改不会重新导入。删除以管理窗口打开时的成员ID为准，因此同代码被删除后重新加入的新记录不会被旧确认误删。关注名单不参与行情保留期清理；移除关注不删除证券资料或快照。操作见[Watchlist](watchlists.md)。

保留期单位是**自然日**。删除条件为 `fetched_at < 当前 UTC 时间 - N 天`，恰好位于边界的数据保留；读取缓存不延长保留期。清理删除旧采集版本，不会裁剪最新日线快照里计算 MA / RSI 等指标所需的历史K线。默认保留天数为0，表示未启用自动删除；由用户指定实际保留期。

```sh
./moomoo db status
# 例如保留180天：设置持久化到当前数据库，桌面 / CLI / MCP 共用
./moomoo db retention --days 180
# 先预览；不删除，也不标记“今天已经清理”
./moomoo db cleanup --older-than-days 180 --dry-run
# 立即执行一次，也可省略天数以使用已保存的保留期
./moomoo db cleanup --older-than-days 180
# 关闭自动清理
./moomoo db retention --days 0
```

启用后，在下一次行情查询或读取桌面收盘结果时检查，每24小时最多执行一次；多个进程共用数据库中的执行记录，通过事务避免重复运行。不要求应用一直运行，也不安装定时任务；程序没运行时不清理，下次查询补做。如果需要系统定时调度，可由外部定时工具执行同一个 `db cleanup` 命令。手动清理的天数只影响本次，不会修改保存的自动策略。

命令返回截止时间、符合条件的快照数、压缩数据大小与实际删除数。当前没有保护旧报告引用的快照：超过所选期限的版本都会被删除，需要长期保留的研究请先导出其完整 JSON 输入。原始数据导出文件不在数据库清理范围内。

SQLite 删除后空闲页供后续写入复用，文件不一定立刻变小。需要归还磁盘空间时，在空闲时单独执行 `./moomoo db vacuum`；它会重整整个数据库，可能阻塞其他写入，并需要额外临时磁盘空间，不随每天自动清理运行。

并发访问使用 WAL 和短事务。备份时退出所有使用该库的程序，再复制数据库；不要在写入期间只复制 `.sqlite3` 而丢掉 WAL。真实行情库不提交到 Git。
